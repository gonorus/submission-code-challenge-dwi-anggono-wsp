# Problem 2: Fancy Form (Token Swap UI)

Hi there! In this directory, I've put together an interactive currency swap interface built for this **Code Challenge**. I wanted to showcase a production-ready approach, so I engineered this application with an **Enterprise-grade Architecture**, strictly adhering to _Clean Code_ principles, _Atomic Design_, and guaranteeing **100% Test Coverage**.

## A Few Assumptions I Made

Before diving into the code, I want to clarify a few design decisions and constraints I kept in mind while building this:

- **Fail-Fast Environment:** Instead of hardcoding fallback API URLs inside the code, I enforced the use of environment variables (`import.meta.env`). This ensures absolute runtime predictability—if the API URL isn't configured, the app will explicitly fail rather than hiding bugs behind fallbacks.
- **Atomic Design:** I structured the React components strictly into `atoms`, `molecules`, `organisms`, and `pages`. This makes everything highly reusable and easy to test in isolation.
- **Semantic Path Aliases:** To avoid messy relative imports like `../../utils`, I configured Vite and TypeScript to use clean aliases like `@api`, `@contexts`, `@molecules`, and `@theme`.
- **Avoiding Coverage Obsession:** While I ensured 100% test coverage for all logic, utilities, hooks, and UI components, I purposely excluded pure boilerplate configurations (`main.tsx`, `vite-env.d.ts`) using Vite's `coverage.exclude`.

## How I Approached the Implementations

Here is a quick overview of the key features I built into this application:

### 1. Real-time Price Engine

Instead of just a simple `fetch`, I integrated `@tanstack/react-query`. This allows the app to smartly fetch, deduplicate, and cache live currency prices. I also added a background-polling mechanism so the prices always stay fresh while the user is typing.

### 2. Premium UI/UX

I built the interface using **Material-UI (MUI)**. To make it feel modern and "fancy," I incorporated a _Glassmorphism_ aesthetic, dynamic micro-animations for interactions, skeleton loaders for data fetching, and a centralized Dark/Light Mode system.

### 3. Absolute Type Safety

The entire codebase is written in strict TypeScript (ES2022). I made sure there are zero `any` bypasses, meaning everything from API responses to component props is 100% type-safe.

## Running the Code Locally

If you'd like to try it out or run my tests, I've set everything up with a modern React + Vite environment.

Since the `.env` file containing the public endpoints (`VITE_PRICE_API_URL` and `VITE_ICON_BASE_URL`) is already included in the repository, you can simply run the following commands to get started:

| Command                      | Description                                |
| ---------------------------- | ------------------------------------------ |
| `npm install`                | Install all dependencies                   |
| `npm run dev`                | Start the local development server         |
| `npm run test`               | Run the unit tests via Vitest              |
| `npm run test -- --coverage` | Generate the 100% Test Coverage report     |
| `npm run typecheck`          | Validate TypeScript types (`tsc --noEmit`) |
| `npm run lint`               | Check code quality using Oxlint            |
| `npm run storybook`          | Explore the interactive component library  |
| `npm run build`              | Compile and bundle for production          |

## How I Tested It

I wrote a robust test suite covering every single line of code. I made sure to test:

- **Form Validation:** Ensuring users can't submit empty amounts, identical currencies, or invalid numbers.
- **UI Interactions:** Simulating clicks, typing, and theme toggling to ensure the UI reacts exactly as expected.
- **API Mocks:** Using `vi.mock` to simulate successful and failed API calls so the tests are completely isolated and reliable.
- **Storybook Previews:** Every major component has a `.stories.tsx` file so they can be visually tested and interacted with in isolation.
